# Hiddify link verification (how the panel's links were tested)

`panel_link_test.go` feeds the exact links generated by the panel into
**Hiddify's own link converter** (github.com/hiddify/ray2sing — the code
Hiddify uses to turn a pasted `masterdns://` / `dnst://` link into a
sing-box outbound) and asserts the outbound struct carries the panel's
tunnel domain, encryption key, encryption method and resolvers (including
a custom ISP resolver).

Result recorded 2026-11-10 — all three panel link forms PASS:

```
link 1 (masterdns:// short)  -> domains=[test-user.example.com] resolvers=[8.8.8.8 1.1.1.1 10.150.2.73] encryption="aes-256-gcm" key=<32-hex> smart_pool=true
link 2 (masterdns:// JSON)   -> domains=[test-user.example.com] resolvers=[8.8.8.8 1.1.1.1 10.150.2.73] encryption="5"          key=<32-hex> smart_pool=true
link 3 (dnst://)             -> domains=[test-user.example.com] resolvers=[8.8.8.8 1.1.1.1 10.150.2.73] encryption="5"          key=<32-hex> smart_pool=true
```

To re-run: check out `hiddify/ray2sing` next to a checkout of
`hiddify/hiddify-sing-box` (its go.mod replaces sing-box with the sibling
dir, submodules included), generate links with the panel
(`MDV_HOME`/`MDV_SERVER_DIR` pointed at temp dirs, call `simple_link`,
`json_link`, `dnst_link` for a test user), put them one per line in a file
with a 4th line `KEY=<the key>`, then run this test with
`PANEL_LINKS=<that file> go test ./ray2sing/ -run TestPanelLinks -v`.
Note: `T.Outbound` does not JSON-marshal its options with plain
encoding/json — assert on the `*option.MasterDNSOptions` struct fields,
as this test does.
